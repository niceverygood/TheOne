# 콜드스타트 전략 (Cold Start)

> **버전** v0.1 · **작성일** 2026-05-22 · **운영주체** 주식회사 바틀
> 매칭 서비스의 최대 난제 = 초기 풀 부족. 첫 큐레이션이 빈약하면 리텐션이 무너진다.

## 1. 핵심 전략 — 동시 온보딩
- 웨이팅리스트(`apps/admin /waitlist`) **상위 100명을 같은 날 동시 온보딩**.
- 목적: 출시 첫날 양측(남/여) 풀을 동시에 확보 → 첫 큐레이션이 비지 않게.
- 선정 기준: 등록 순번(seq) + **성비 균형** + **지역 균형**(수도권 편중 보정) + 직군 다양성.

## 2. 실행 절차 (D-3 ~ D-day)
1. **D-3**: 상위 100명 추출 → 성비/지역 균형 보정 후 명단 확정. CSV는 `/waitlist/export`.
2. **D-2**: 초대 발송(알림톡/메일) — "심사 우선 + 첫날 한정 혜택" 안내.
3. **D-1**: 가입·인증 사전 안내, CS 대기조 편성.
4. **D-day 00:00**: 첫 큐레이션 일괄 발송(`/api/cron/curation`). 운영자 모니터링.
5. **D+1~7**: 반응(액션) 모니터링, 매칭 성사율 추적, 큐레이션 가중치 수동 조정.

## 3. 첫 큐레이션 풀 확보 체크
- [ ] 활동 회원 ≥ 80명, 성비 40:60~60:40 이내
- [ ] 각 회원에게 `isEligible` 후보 ≥ 3명 (지역·나이 필터 통과)
- [ ] 후보 0명 회원 비율 < 10% (제주 등 고립 지역 점검)
- [ ] 인증 뱃지 보유율 ≥ 50% (큐레이션 점수 변별력)

## 4. 부족 시 대응
- 후보 0명 회원: 나이 윈도우 한시 ±7 확대 또는 인접 지역 가중치 상향(`packages/shared/matching.ts WEIGHTS`).
- 성비 불균형: 부족 측 초대 추가 발송. 심한 편향 시 출시 연기 검토(게이트).
- 직군 70%+ 편향: 카피·타겟 재점검(Phase 1 게이트 메모와 동일 기준).

## 5. 측정 (ops-runbook.md KPI와 연계)
- 첫날 큐레이션 발송/조회/액션 수, 첫 신청서까지 시간, 첫 매칭까지 시간, D1 리텐션.

> **결정 필요**: 동시 온보딩 인원(100 vs 200), 첫날 한정 혜택(무료 슈퍼 신청서 1회 등) 범위.
